# Asas v0.2.0 — Core Enhancements Design

- **Date:** 2026-11-09
- **Status:** Approved in conversation; awaiting written-spec review
- **Scope:** Sub-project A of two. Sub-project B (OpenAPI → code CLI) gets its own spec
  and will generate code in the style defined here.

## 1. Goals

Asas is a decorator-based SDK builder whose product is developer experience. v0.2.0 is a
**breaking** release (permitted under 0.x) that:

1. Makes decorated methods type-check correctly **from the caller's side**.
2. Gives explicit control over where each parameter goes (path, query, header, cookie,
   JSON body, form, multipart file), with aliases — required for OpenAPI coverage.
3. Fixes correctness gaps: silent HTTP errors, non-JSON-safe body dumps, unencoded path
   values, ignored httpx timeouts, mistyped `Payload.json`, and missing client lifecycle.
4. Adds a typed error hierarchy and lifecycle event hooks.
5. Makes resources generic so CRUD returns are typed.

### Success criteria

- `assert_type(client.get_user(1), User)` passes under `mypy --strict` (enforced by a
  typing test run in `make type-check`).
- Every OpenAPI parameter location (`path`, `query`, `header`, `cookie`) and body kind
  (`application/json`, `application/x-www-form-urlencoded`, `multipart/form-data`) is
  expressible in a single decorated method.
- Declaration mistakes fail at **import time** with a clear `TypeError`.
- Non-2xx responses raise a typed exception by default.
- `make test`, `make type-check`, and `make lint` pass on Python 3.10–3.13.

### Non-goals (v0.2)

Async hooks, middleware / retry / backoff, the testing module, GraphQL, the OpenAPI CLI,
and preserving v0.1 source compatibility.

## 3. Endpoint declaration convention

The return annotation drives parsing. The method body is **never executed**; the
documented body is `raise NotImplementedError` (mypy strict rejects a bare `...` body
with `[empty-body]`, verified with mypy 2.1). No parameter is injected.

```python
class Users(AsasClient):
    @get("/users/{id}")
    def get_user(
        self,
        id: int,
        expand: Annotated[str | None, Query(alias="x-expand")] = None,
        trace: Annotated[str | None, Header("X-Trace")] = None,
    ) -> User:
        raise NotImplementedError

user = client.get_user(1)          # typed: get_user(id, expand, trace) -> User
```

Async is detected via `inspect.iscoroutinefunction`; `async def ... -> User` returns
`User` when awaited. Decorators are typed `Callable[[F], F]`, so callers see the
declared signature unchanged.

Post-processing is done by an ordinary method that calls the endpoint, or by a hook.

### Decorator signature

```python
def get(  # likewise post, put, patch, delete
    path: str,
    *,
    headers: Mapping[str, str] | None = None,
    timeout: float | None = None,
    use_auth: bool = True,
    raise_for_status: bool | None = None,   # None = inherit from client
    hooks: Hooks | None = None,
) -> Callable[[F], F]: ...
```

`response_model` is **removed**; the return annotation replaces it.

## 4. Architecture

Each endpoint is compiled once, at decoration time, into an `EndpointSpec`. One shared
pipeline executes it; only the transport call differs between sync and async. This
replaces the duplicated `async_inner` / `sync_inner` request-building and parsing logic.

```
asas/
  params.py        # Path/Query/Header/Cookie/Body/Form/File markers (+ Location enum)
  errors.py        # AsasError hierarchy, status→class map, Retry-After parsing
  hooks.py         # Hooks dataclass and run helpers
  endpoint.py      # EndpointSpec: compile, build_request, parse_response
  decorators.py    # get/post/put/patch/delete → EndpointSpec; execute_sync/execute_async
  client.py        # + hooks, raise_for_status, close()/aclose(), context managers
  core/models.py   # Payload.json: Any, Payload.data, Request.cookies
  engines/         # honour timeout, map cookies, wrap transport errors
  resource.py      # Generic resources; CRUD runs through the shared pipeline
```

### EndpointSpec

Built by `EndpointSpec.compile(method, path, func, options)`:

- `method`, `path` (template), `is_async`
- `params: list[ParamSpec]` where `ParamSpec(name, location, alias, annotation, marker,
  adapter)`; `adapter` is a cached `TypeAdapter(annotation)`
- `return_kind: Literal["response", "none", "bytes", "str", "model"]` and a cached
  `TypeAdapter` for `"model"`
- `returns_optional: bool` (whether `None` is a valid result, for empty bodies)
- endpoint options: `headers`, `timeout`, `use_auth`, `raise_for_status`, `hooks`

Annotations are resolved with `typing.get_type_hints(func, include_extras=True)`.

Methods:

- `build_request(client, args, kwargs) -> Request` — binds arguments and routes each
  value per its `ParamSpec`. Does not apply auth.
- `parse_response(response) -> Any` — per section 6.

## 5. Parameters and request building

### Markers (`asas/params.py`)

| Marker | Destination | Notes |
|---|---|---|
| `Path(alias=None)` | URL segment | `urllib.parse.quote(str(v), safe="")` |
| `Query(alias=None)` | query string | list/tuple → repeated keys (`?tag=a&tag=b`) |
| `Header(alias=None)` | headers | default alias: `x_trace` → `X-Trace` |
| `Cookie(alias=None)` | `Request.cookies` | |
| `Body(exclude_unset=False, exclude_none=False)` | JSON body | at most one per endpoint |
| `Form(alias=None)` | form-encoded body | many allowed |
| `File(alias=None)` | multipart body | value: `bytes`, binary file object, or `(filename, content, content_type)` |

`Header`'s alias may be passed positionally (`Header("X-Trace")`); all other arguments
are keyword-only.

### Inference without a marker (from the annotation, at compile time)

1. Name matches a `{placeholder}` in the path → `Path`.
2. Annotation (after stripping `Optional`) is a `BaseModel` subclass, `list[BaseModel]`,
   or `dict[...]` / `dict` → `Body`.
3. Otherwise → `Query`.

### Compile-time validation (each raises `TypeError` naming the method)

- A `{placeholder}` has no matching parameter (by name or `Path` alias).
- A `Path` parameter has no matching placeholder.
- More than one `Body` parameter.
- `Body` combined with `Form` or `File`.
- Two parameters resolve to the same wire name in the same location.
- The return annotation is missing (hint: use `-> Response` for the raw response).
- A parameter lacks a type annotation.

### Serialization

- Every value is dumped through its cached adapter:
  `adapter.dump_python(value, mode="json", by_alias=True)`. This makes `datetime`,
  `date`, `UUID`, `Decimal`, enums, and aliased model fields work in every location.
- `Body` additionally passes `exclude_unset` / `exclude_none` from its marker.
- Query/header/cookie/form/path scalars are converted to `str` after dumping; booleans
  become `"true"` / `"false"`.
- `None` values are omitted from query, headers, cookies, and form. A `None` path value
  raises `ValueError` at call time.
- Form + File together produce one multipart body; Form alone is form-encoded.

### Header precedence (lowest → highest)

Client default headers (engine kwargs) → endpoint `headers=` → `Header()` params → auth.

### Core model changes (`asas/core/models.py`)

```python
@dataclass
class Payload:
    data: dict[str, Any] | bytes | None = None   # form fields or raw bytes
    json: Any = None                              # was Dict[str, Any]
    files: dict[str, Any] | None = None
    headers: dict[str, str] = field(default_factory=dict)

@dataclass
class Request:
    method: str
    url: str
    params: dict[str, Any] | None = None
    headers: dict[str, str] = field(default_factory=dict)
    cookies: dict[str, str] = field(default_factory=dict)   # new
    payload: Payload | None = None
    timeout: float | None = None
```

`APIKeyAuth` with `APIKeyLocation.COOKIE` writes to `Request.cookies` instead of a raw
`Cookie` header.

### Engines

- **httpx:** pass `timeout=request.timeout` when set (via request extensions /
  `httpx.Timeout`), map `cookies`, send `data` dict as form, `bytes` as `content`.
- **requests:** map `cookies`; send `data` + `files` together for multipart.
- Both catch their library's transport exceptions (`httpx.TransportError`,
  `requests.RequestException`) and raise `asas.TransportError(request=...) from exc`.
  This is a documented requirement of the engine contract (`docs/engines.md`).

## 6. Response parsing

| Return annotation | Result | Raises on non-2xx |
|---|---|---|
| `Response` | raw `Response` | never |
| `None` | `None`, body discarded | yes |
| `bytes` | `response.content` | yes |
| `str` | `response.text` | yes |
| any other `T` | `TypeAdapter(T).validate_json(response.content)` | yes |

- Empty body: returns `None` if `T` admits `None`; otherwise `ResponseValidationError`.
- Pydantic `ValidationError` (and JSON decode errors) are wrapped in
  `ResponseValidationError`.

## 7. Errors (`asas/errors.py`)

```
AsasError
├── HTTPStatusError(request, response)          .status_code
│   ├── ClientError                              4xx fallback
│   │   ├── BadRequestError            400
│   │   ├── UnauthorizedError          401
│   │   ├── ForbiddenError             403
│   │   ├── NotFoundError              404
│   │   ├── ConflictError              409
│   │   ├── UnprocessableEntityError   422
│   │   └── RateLimitError             429      .retry_after: float | None
│   └── ServerError                              5xx fallback
│       ├── InternalServerError        500
│       └── ServiceUnavailableError    503
├── ResponseValidationError(response, error)    wraps pydantic / JSON errors
└── TransportError(request)                     raised by engines, chained `from`
```

- `raise_for_status` resolution: endpoint value → client value → `True`.
- Any non-2xx status raises (1xx/3xx included, since engines follow redirects per their
  own config); the most specific class wins, else `ClientError` / `ServerError`, else
  `HTTPStatusError`.
- Message: `"GET https://api.example.com/users/1 → 404 Not Found: <first 200 chars of body>"`.
- `RateLimitError.retry_after` parses `Retry-After` as delta-seconds or an HTTP-date
  (converted to seconds from now, minimum 0); `None` if absent or unparseable.
- Status errors are raised **after** the auth refresh/challenge retry has been attempted.
- All error classes are exported from `asas/__init__.py`.

## 8. Hooks (`asas/hooks.py`)

```python
@dataclass
class Hooks:
    on_request: list[Callable[[Request], Request | None]] = field(default_factory=list)
    on_response: list[Callable[[Request, Response], None]] = field(default_factory=list)
    on_error: list[Callable[[AsasError], None]] = field(default_factory=list)
```

- Plain synchronous callables; the same hooks work with sync and async clients. Docs
  state hooks must not block on I/O.
- `on_request` may mutate and return `None`, or return a replacement `Request`.
- Order: client hooks, then endpoint hooks.
- `on_error` is observational: it runs before any `AsasError` is raised by the pipeline
  and cannot suppress it.
- Exceptions raised by a hook propagate unchanged.

### Pipeline

```
spec.build_request → auth.apply (if use_auth) → on_request* → engine.send
    → on_response*
    → if 401 and auth is ChallengeResponseAuth / RefreshableAuth (existing rules):
          refresh/challenge → rebuild → auth.apply → on_request* → send → on_response*
          (exactly once, unchanged semantics)
    → status check   (HTTPStatusError)
    → spec.parse_response   (ResponseValidationError)
    → return
TransportError, HTTPStatusError, ResponseValidationError → on_error* → raise
```

`execute_sync` / `execute_async` own this pipeline and are shared with resources.

## 9. Client

```python
class AsasClient(BaseAsasClient[SyncEngine]):
    def __init__(
        self,
        base_url: str = "",
        *,
        engine: SyncEngine | None = None,
        auth: Auth | None = None,
        hooks: Hooks | None = None,
        raise_for_status: bool = True,
        **engine_kwargs: Any,          # forwarded to HTTPXSyncEngine when engine is None
    ) -> None: ...

    def close(self) -> None: ...
    def __enter__(self) -> Self: ...
    def __exit__(self, *exc: object) -> None: ...   # calls close()
```

`AsasAsyncClient` mirrors this with `aclose()`, `__aenter__`, `__aexit__`. `Self` comes
from `typing_extensions` (added as a dependency) on 3.10.

- The client always closes its engine. Sharing one engine across clients means closing
  the engine directly; documented in `clients.md`.
- `auth` remains a settable property; `hooks` is a public attribute.

## 10. Generic resources

```python
ModelT = TypeVar("ModelT")

class AsasResource(BaseResource, Generic[ModelT]):
    def list(self, **params: Any) -> list[ModelT]: ...
    def get(self, id: Any) -> ModelT: ...
    def create(self, obj: ModelT) -> ModelT: ...
    def update(self, id: Any, obj: ModelT) -> ModelT: ...   # PUT, unchanged
    def delete(self, id: Any) -> None: ...                  # was -> Response
    def iterate(self, **params: Any) -> Iterator[ModelT]: ...
    def __iter__(self) -> Iterator[ModelT]: ...

class Users(AsasResource[User]):
    path = "/users"
```

- `model` is inferred from the generic argument via `__orig_bases__` in
  `__init_subclass__`; an explicit `model = ...` class attribute or constructor argument
  overrides it. A bare `AsasResource` (no type argument, no `model`) yields raw JSON
  (`ModelT` is `Any`).
- `AsasAsyncResource[ModelT]` mirrors this with `async` methods and `AsyncIterator`.
- CRUD and pagination requests run through `execute_sync` / `execute_async`, so they
  raise typed errors and fire client hooks.
- Custom endpoints on resources use the section 3 convention.
- Model bodies use the same JSON-safe, alias-aware dump as section 5.

## 11. Public API (`asas/__init__.py`)

Added to `__all__`: `Path`, `Query`, `Header`, `Cookie`, `Body`, `Form`, `File`,
`Hooks`, `AsasError`, `HTTPStatusError`, `ClientError`, `ServerError`,
`BadRequestError`, `UnauthorizedError`, `ForbiddenError`, `NotFoundError`,
`ConflictError`, `UnprocessableEntityError`, `RateLimitError`, `InternalServerError`,
`ServiceUnavailableError`, `ResponseValidationError`, `TransportError`.

`Path` shadows nothing in asas itself; docs recommend `from asas import Path` only when
`pathlib.Path` is not also needed, otherwise `import asas` and `asas.Path`.

## 14. Breaking changes (summary for the migration guide)

1. Endpoint bodies no longer receive the parsed result; return annotation drives parsing.
2. `response_model=` removed.
3. Non-2xx responses raise by default.
4. Parameter routing is decided from annotations, not runtime values; unannotated
   `dict` parameters now go to the body, not the query string.
5. Python 3.9 dropped.
6. Client constructor arguments after `base_url` are keyword-only.
7. `Resource.delete()` returns `None` instead of `Response`.
8. `APIKeyAuth` cookie location uses `Request.cookies`.
9. Custom engines must wrap transport exceptions in `TransportError` and honour
   `Request.cookies`.
